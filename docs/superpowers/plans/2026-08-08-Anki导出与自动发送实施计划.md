# Anki 导出历史与启动自动发送实施计划

> **面向执行代理：** 必须使用 `subagent-driven-development` 或 `executing-plans` 按任务执行，所有行为变更先写失败测试再实现。

**目标：** 在卡片库提供可回顾的 Anki 批次导出，并在应用启动时确保最近 24 小时内至少成功发送过 1 张复习卡。

**架构：** 手动导出使用 `output/anki/exports/` 下的 `.apkg`、Markdown 和 JSON 元数据作为本地历史；启动发送时间使用现有 `app_settings`。导出、自动发送和界面分别放在独立模块，最后仅在路由和服务入口集中组装。

**技术栈：** TypeScript、Express、SQLite、React、Vitest、Testing Library、现有 Anki APKG 生成器与 cc-connect 发送器。

---

## 文件责任边界

- `server/anki/source.ts`：提供按全部或指定卡片编号读取并去重初始稿的能力。
- `server/anki/libraryExports.ts`：创建、列举、读取和重新下载手动导出批次。
- `server/anki/daily.ts`：允许自动发送使用独立文件前缀。
- `server/anki/autoSend.ts`：实现 24 小时成功发送判定和并发合并。
- `server/anki/routes.ts`、`server/index.ts`：只负责组装接口和启动检查。
- `src/pages/CardsPage.tsx`、`src/styles/cards-glass.css`：只负责卡片库按钮、状态和底部历史面板。
- 公共入口、锁文件、文档和 `progress.md` 由主线程单写。

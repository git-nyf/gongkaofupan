# 卡片库页码跳转设计

## 目标

在卡片库现有分页控件中支持直接输入页码跳转，减少卡片数量较多时连续点击上一页或下一页的操作成本，同时保留当前玻璃材质、左右翻页按钮和 URL 可恢复能力。

## 交互设计

分页控件中间由静态“第 1 / 21 页”改为“第 [1] / 21 页”的紧凑数字输入布局。

- 输入框只接受数字，初始值与当前有效页一致。
- 按 `Enter` 或输入框失焦时提交跳转。
- 按 `Escape` 放弃未提交内容，恢复当前页并移出输入焦点。
- 空值或非有效数字不触发请求，恢复当前页。
- 小于 `1` 的页码按第 `1` 页处理；超过总页数的页码按最后一页处理。
- 输入当前页不产生重复跳转或额外请求。
- 卡片加载期间禁用页码输入，与左右翻页按钮保持一致。
- 翻页、筛选变化、接口自动纠正越界页码后，输入框同步显示新的有效页码。

## 数据流

页码提交后复用现有分页状态更新入口，将校验后的页码写入 URL 的 `page` 参数。现有卡片列表副作用继续根据 URL 筛选状态发起请求，不新增服务端接口或数据库字段。

## 视觉与可访问性

- 输入框保留在现有薄玻璃分页容器内，不增加单独的“跳转”按钮。
- 输入框尺寸稳定，最多容纳当前总页数所需位数，不因内容变化推动左右按钮。
- 使用数字输入模式，并提供明确的“页码”无障碍名称。
- 聚焦时使用现有红色强调色和清晰焦点环；禁用态与左右按钮保持一致。
- 移动端维持至少 44 像素的可操作高度，文字放大时分页内容不得重叠。

## 验证标准

- 输入有效页码并按 `Enter` 后，URL 和卡片请求切换到目标页。
- 输入页码后失焦同样提交。
- `Escape`、空输入、超出上下界和当前页输入均符合上述规则。
- 加载期间输入被禁用，加载完成后恢复。
- 既有上一页、下一页、筛选分页和 URL 越界纠正测试继续通过。

# 卡片库用户初始稿文件夹设计

## 目标

在卡片库切换到“用户初始稿”后，于主卡片列表上方提供文件夹区域。用户可以新建和删除文件夹，把下方任意初始稿卡片拖入文件夹；拖入只建立引用，主列表中的卡片保持不变。

## 范围

- 文件夹只服务于“用户初始稿”视图，AI 优化稿视图不显示文件夹区域。
- 支持新建文件夹、删除文件夹、点击查看文件夹内容和拖入初始稿。
- 删除文件夹只删除文件夹及其引用，不归档、不删除、不修改任何卡片。
- 同一份初始稿重复拖入同一文件夹时保持一份，不产生重复副本。
- 本轮不增加文件夹改名、文件夹排序、文件夹内手动排序或单独移出卡片。

## 方案选择

采用 SQLite 文件夹表与卡片引用表。浏览器本地存储无法进入备份且清理站点数据后会丢失；直接保存初始稿原文会复制业务数据并在编辑后失效。关系表只保存稳定卡片编号，不复制原文，是当前需求下最小且可靠的实现。

拖入一份初始稿时，前端提交该初始稿当前全部衍生卡片编号，服务端逐项建立幂等引用。读取文件夹内容时，服务端先从仍存在的引用卡片恢复初始稿来源，再展开该来源当前全部衍生卡片。这样编辑初始稿时即使旧衍生卡片被替换，保留下来的锚点卡仍能维持文件夹引用，新衍生卡也会随来源展开自动出现。

## 数据结构

迁移版本 5 新增两张表：

- `card_folders`：`id`、`name`、`created_at`、`updated_at`。名称去除首尾空白后长度为 1 至 40 个字符，同名文件夹不允许重复。
- `card_folder_items`：`folder_id`、`card_id`、`created_at`，以文件夹和卡片编号作为联合主键。两个外键都启用级联删除；删除文件夹只清理关联，删除真实卡片只清理对应失效引用。

不修改现有卡片表，也不迁移或重写已有卡片数据。

## 接口

- `GET /api/cards/folders`：返回全部文件夹、每个文件夹内按初始稿来源去重后的数量。
- `POST /api/cards/folders`：新建文件夹，请求体为 `{ name }`。
- `DELETE /api/cards/folders/:folderId`：删除文件夹及其引用，成功返回 204。
- `GET /api/cards/folders/:folderId/cards`：返回文件夹概要及按当前卡片库规则排序的用户初始稿内容。
- `POST /api/cards/folders/:folderId/cards`：把 `{ cardIds }` 中存在的初始稿组成员幂等加入文件夹，返回更新后的文件夹概要。

所有接口严格拒绝未知字段、空编号、超长名称和不存在的文件夹；错误响应使用现有安全错误格式，不暴露 SQL 或本机路径。

## 前端交互

文件夹区域位于内容版本切换器下方、主卡片网格上方，使用现有白色液态玻璃和紧凑工具栏样式。

- “新建文件夹”使用内联名称输入与图标按钮，Enter 与按钮提交共用同一请求。
- 文件夹以小型文件夹卡片横向排列，显示名称和初始稿数量；点击后展开其内容预览，再次点击收起。
- 文件夹删除使用垃圾桶图标和现有确认框，确认文案明确说明不会删除卡片。
- 用户初始稿卡片启用原生拖拽。拖过文件夹时提供边框、抬升和轻微弹性反馈，离开或取消时立即恢复；成功放入后更新数量和已展开内容，主列表不移除、不刷新分页。
- 文件夹内容复用现有初始稿卡片展示和详情预览，只作为副本查看，不重复提供归档、置顶和删除操作。
- 减少动态效果模式取消抬升和位移，仅保留边框与颜色反馈；键盘用户仍可通过卡片上的“加入文件夹”菜单完成同一操作，避免拖拽成为唯一入口。

## 状态与错误

文件夹列表、活动文件夹内容和主卡片列表分别管理加载状态。新建、删除或加入失败时保留当前内容并显示稳定提示；重复加入视为成功。请求期间只禁用相关文件夹控件，不阻塞卡片搜索、分页和查看详情。

## 验证

- 迁移测试覆盖新表、外键、幂等迁移和旧数据库数据保持不变。
- 服务端测试覆盖新建、重名、删除不删卡、重复加入、来源去重、编辑后展开和安全错误。
- 前端测试覆盖只在用户初始稿显示、新建、删除确认、拖入后主列表保留、重复加入、点击查看、键盘加入、失败保持和减少动态效果。
- 完成后运行卡片专项、全量测试、类型检查、生产构建，并在桌面与 390 像素视口做真实浏览器验收。

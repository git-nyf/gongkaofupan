# 本地运行与数据管理

## 环境要求

- Node.js 版本不低于 22.12。
- 使用 npm 安装和运行项目依赖。

## 安装与开发启动

首次运行时执行：

```powershell
npm install
Copy-Item .env.example .env
npm run dev
```

开发服务仅监听本机。后端端口由 `PORT` 配置，系统环境变量优先于 `.env`；Vite 的 `/api`、`/uploads` 开发代理复用同一端口。使用默认端口时，前端地址为 `http://127.0.0.1:5173`，后端健康检查地址为 `http://127.0.0.1:8787/api/health`。

开发代理对 API 与上传路径采用大小写不敏感的精确边界；根路径携带查询参数时仍会代理，`/apiary`、`/uploads-old` 等相似前缀不会代理。

`package-lock.json` 必须随依赖变更提交，并保留 `@types/better-sqlite3` 开发依赖，以支持服务端 TypeScript 导入 SQLite 驱动。服务端依赖基线为 Express 4 类型声明与 Multer 2；安装完成后执行 `npm run typecheck` 验证类型依赖可用。

## 构建与运行

执行以下命令生成前后端构建产物并启动构建服务：

```powershell
npm run build
npm start
```

`npm start` 会设置 `NODE_ENV=production`，避免 Express 返回开发环境错误堆栈。前端构建产物位于 `dist/client`，服务端构建产物位于 `dist-server`。

## 配置与数据

本地配置从 `.env` 读取，默认数据目录为项目下的 `./data`，运行时会解析为绝对路径。DeepSeek 模型固定为 `deepseek-v4-flash`。`.env` 只供本机使用，可能包含 DeepSeek 密钥，禁止提交到版本库；提交配置示例时只能保留空密钥。

### DeepSeek 密钥与数据边界

只在本机 `.env` 的 `DEEPSEEK_API_KEY` 中配置新密钥，不得把密钥写入源码、文档或提交记录；已经暴露或使用过的旧密钥必须先在 DeepSeek 侧撤销。自动整理时，录入模式（`entry_mode`）、卡片原文、所选分类、模板和五个现有固定字段会发送到 DeepSeek。

未配置 `DEEPSEEK_API_KEY` 或其值只有空白时，系统不会发起 DeepSeek 请求。新建卡片仍会先完整保存到本地，随后标记为 `pending` 并记录 `not_configured` 错误码；服务启动时也会跳过待整理卡片的批量重试，避免无意义增加尝试次数。配置密钥后可以手动重新整理，或在后续启动时由批量重试继续处理。

单次请求使用 20 秒超时。只有空响应、非法 JSON 或结构校验失败会重试一次，总计最多请求两次；HTTP 错误和超时不重试，读取响应正文时发生超时或断流也不重试。非 2xx HTTP 响应会先释放响应体，再返回统一的脱敏错误。AI 契约测试全部使用注入的假网络响应，不需要真实密钥，也不会访问真实 DeepSeek 网络。

卡片创建会先在本地事务中保存原文、分类、用户标签、模板和已经验证的附件元数据，提交后才调用 DeepSeek。整理成功时状态为 `ready`；无法安全生成题面时状态为 `needs_input`；AI 或整理入库失败时保留原卡片并标记为 `pending`，数据库只保存稳定错误码，不保存原始异常消息。用户已经填写的错误点、解析、口诀、拓展和笔记不会被 AI 空字符串清空。

服务启动前会把持续 `processing` 达到五分钟的卡片恢复为 `pending`。监听成功后会异步重试最多二十张 `pending` 卡片，单张失败不会阻塞服务启动或其余卡片；`pending` 和 `needs_input` 卡片也可以通过重新整理接口再次尝试。模板保存在每张卡片的 `cards.template` 字段中，因此创建、手动重试和启动批量重试会使用同一模板重建 AI 输入。

### 卡片管理接口

`GET /api/cards` 返回 `{ items, total, page, pageSize }`。查询参数包括 `query`、`categoryIds`、`tagIds`、`rating`、`mastery`、`aiStatus`、`archived`、`createdFrom`、`createdTo`、`page` 和 `pageSize`；分类和标签编号使用重复查询键传入，例如 `categoryIds=常识判断&categoryIds=常识判断/文史`。筛选条件之间使用 AND，分类数组内部和标签数组内部使用 ANY；标签编号按关系精确匹配，`query` 对原文、规范表述、解析、口诀、拓展、笔记和标签名进行字面包含搜索。

`archived` 默认值为 `false`，因此默认列表不返回已归档卡片。`page` 默认值为 1，`pageSize` 默认值为 20且最大为 100，排序固定为创建时间倒序、卡片编号倒序。`createdFrom` 和 `createdTo` 接受 ISO 日期时间或 `YYYY-MM-DD`；仅传日期时分别按该日 UTC 的 `00:00:00.000Z` 和 `23:59:59.999Z` 处理，开始时间晚于结束时间会返回 400。

`GET /api/cards/:id` 读取详情，`PATCH /api/cards/:id` 更新请求中明确提供的字段，`DELETE /api/cards/:id` 删除卡片。更新分类时仍须同时包含至少一个一级分类和一个二级分类；`userTags` 替换用户来源标签并保留 AI 来源标签，同名 AI 标签会升级为用户来源。处于 `needs_input` 的卡片只有在原文实际变化时才会自动重新整理，单独修改星级、标签或归档状态不会调用 AI。卡片处于 `processing` 时，修改原文、AI 固定字段、分类、模板或掌握度等 AI 相关内容会返回 409，避免在途整理结果覆盖新内容；用户标签、来源信息、星级和归档状态仍可修改。

`PATCH /api/cards/bulk` 的请求体形状为 `{ ids, rating?, tags?, archived? }`，其中 `tags` 表示添加标签。重复编号会去重，不存在的编号会忽略，响应 `{ updated }` 只统计实际存在且命中的卡片。批量字段和标签在同一 SQLite 事务内写入。

### 本地图片接口

JSON 格式的 `POST /api/cards` 保持原有请求形状，`attachments` 必须为空数组。使用 `multipart/form-data` 创建时，必须且只能有一个文本字段 `payload`，其值为同一创建请求的 JSON 字符串且 `attachments` 仍为空数组；其余文件字段均作为图片。系统只接受 `image/png`、`image/jpeg` 和 `image/webp`，单张图片不能超过 10MB，不检查用户文件名来决定存储路径。

`POST /api/cards/:id/attachments` 为已有卡片添加至少一张图片，成功返回更新后的卡片详情。`DELETE /api/cards/:cardId/attachments/:attachmentId` 仅在附件确实属于该卡片时删除，`GET /uploads/:storedName` 只读取系统生成的 UUID 文件名。图片使用 UUID 和固定的 `.png`、`.jpg`、`.webp` 扩展名保存到数据目录下的 `uploads` 目录，默认位置为 `data/uploads`；原文件名只作为附件元数据保存，不参与路径拼接。

创建卡片或添加附件时，全部图片完成格式和大小校验后才写入本地目录。随后 SQLite 事务失败时会清理本轮已经写入的全部 UUID 文件；删除附件或卡片时顺序相反，先提交数据库删除和外键级联，再删除对应本地文件。文件已经不存在时视为清理完成，其他文件删除错误返回安全的内部错误，但不会声称已经提交的数据库事务被回滚。

### SQLite 数据库

数据库文件位于数据目录下的 `gongkao.db`，默认路径为项目根目录的 `data/gongkao.db`。首次启动服务时会自动创建数据目录、数据库表并写入公考分类目录；后续启动只执行幂等迁移，不会重复写入分类。迁移按版本顺序执行并记录到 `schema_migrations`；版本 2 的 `002_card_template.sql` 会为已有版本 1 数据库增加卡片模板字段，原卡片保留且模板默认值为空字符串。

每次打开数据库连接都会启用 WAL 日志模式和外键约束，以保证本地读写和关联数据删除按既定规则执行。删除整个 `data` 目录会永久移除本机数据库及其中的卡片、复习记录和设置；没有独立备份时无法恢复，删除前必须确认不再需要这些数据。

替换数据库时会先从源库生成包含 WAL 当前内容的一致快照，在同目录暂存库中完成完整性检查和迁移，再通过重命名原子换入；换入失败时使用单次临时回滚文件恢复原库，成功或恢复后会清理暂存文件。业务代码应持有数据库 manager，并在每次操作前调用 `get()` 获取当前连接，不应长期缓存裸连接。

当前连接存在尚未结束的查询时，数据库替换会拒绝执行并清理本轮暂存文件，原数据库保持可用；释放查询后可以重新发起替换。
